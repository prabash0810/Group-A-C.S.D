DayWise Project Documentation
1. Project Overview
DayWise is a client-side web application built to help students manage different aspects of their daily lives in one place. It brings together academic planning, work schedules, task lists, events, achievements, financial tracking, and personal goals into a unified interface. The goal is to replace multiple separate apps with a single organized “dashboard” for student life. For example, apps like MyStudyLife show that students benefit from having tasks, classes, and assignments in one place: MyStudyLife “keeps track of classes to attend and assignments due” and lets students plan revision with reminders. DayWise takes a similar approach by giving students a simple, unified interface for planning. Users can log in once and then navigate to any section (classes, work shifts, finances, events, etc.) without jumping between different websites.
DayWise was developed as a team project, with four members each responsible for different parts of the site. Each person implemented specific features (like the Daily Planner or Dashboard) and also helped with testing, documentation, and project management. Everyone collaborated through Git/GitHub, so each commit and feature is tracked, and all code is integrated into one repository. This team approach allowed us to work on multiple features in parallel while maintaining a consistent look and feel.
2. Main Features
The DayWise website is organized into several sections, each as its own webpage with its own JavaScript logic. The main features include:
Login Page: The entry point to DayWise. It handles user authentication and redirects to the main Dashboard after a successful login. (In our project, this could be a simple form; in a real app it might connect to a server or Firebase.)
Dashboard: A home overview page. It collects information from different parts of the app (upcoming classes, tasks, events, etc.) and displays them in one place, giving the user a quick summary. Dashboards like this are common in web apps to present key data at a glance.
Daily Planner: Allows students to plan their day hour-by-hour or block-by-block. Users can add tasks or schedule items into each time slot. This helps with time management by letting students organize their day in detail.
Work & Study: Lets users manage their university classes and work shifts in one place. For example, a student can enter class schedules (course name, time, room) and work shift details. This section uses the browser’s Local Storage to save the information. Local Storage is a standard web API for storing key/value data that persists across page reloads and even after the browser is closed. In DayWise, this means any classes or shifts the user adds will remain in the browser until they delete them, so the data is not lost on a refresh.
Money Manager: A simple finance section for tracking income and expenses. Students can log purchases or income, helping them stick to a budget. (Many students use budgeting apps to keep track of money; DayWise integrates a basic version of this, inspired by personal finance tools.)
Events & Achievements: A place to record important events (like deadlines, exams, or social plans) and personal achievements (like winning a contest or completing a project). Having events and achievements in one place helps students remember key dates and celebrate milestones.
Settings: Contains options to customize the app (for example, user preferences or a “dark mode” toggle). It provides a way to change the application’s behavior or appearance.
Dark Mode: As part of Settings or as a site-wide option, DayWise supports a dark-themed interface. Dark mode is popular because it can reduce eye strain and save battery life on modern devices. Our implementation lets the user switch between light and dark themes so the app is more comfortable to use in low-light environments.
Common Navigation and UI: All pages share a consistent navigation menu or header so the user can move between sections (Dashboard, Planner, Work & Study, etc.) easily. The consistent design and menus make the app feel like one unified site rather than disjointed pages.
HTML and CSS are used for the page structure and styling, while JavaScript handles the interactivity. As MDN explains, “HTML … defines the meaning and structure of web content, [and other technologies] describe a web page’s appearance (CSS) or functionality (JavaScript)”. In DayWise, HTML files give each page its content, CSS files handle colors and layouts (including dark mode), and JavaScript adds features like adding or deleting items.

4. Team Development
The DayWise team organized the work by dividing the app into sections, with each person taking one or two main sections. We used Git and GitHub for version control. A distributed VCS like Git lets each developer work on their own machine; we committed changes locally and then pushed them to the shared repository. This workflow meant we could integrate our work regularly by merging branches. For example, we had a dev branch for integration and used feature branches for each part. Using Git meant we could track changes over time (each commit records the author and message) and roll back if needed.
We coordinated through GitHub issues and pull requests. When one member finished a feature (say, the Daily Planner), they opened a pull request on GitHub. Teammates reviewed the code for errors or improvements before merging. This review process helped catch bugs early. If two members modified the same file (e.g. styling or navigation code), Git sometimes reported merge conflicts. We resolved these by communicating which change to keep (the version control system logs conflict markers so we could edit the files manually). In the end, the repository’s history shows each member’s contributions (commits are linked to author accounts) and the final README.md was updated with project information.
Working this way taught us good collaboration: having a shared central repository meant we all “pulled” the latest code before starting work, to avoid duplication. We practiced basic Git skills: branching, committing, pushing, pulling, merging, and pushing again. A distributed approach allowed us to experiment locally without immediately affecting others, then share only when ready. This collaboration ensured that by the end, all sections were integrated into one cohesive application.
5. Documentation and Architecture
We kept documentation up to date throughout the project. The main README file in the repository explains what DayWise is, how to run it, and describes its features. It includes an overview of the app and file structure. Markdown formatting was used so the documentation is easy to read on GitHub.
To illustrate the structure of the application, we used Mermaid diagrams in the README. Mermaid lets you write text-based diagrams inside fenced code blocks, and GitHub renders them as visuals. For example, we created a flowchart showing how the HTML pages, JavaScript scripts, and browser storage (Local Storage, etc.) connect. This visual architecture diagram helps new developers and users understand how DayWise is organized.
Each part of the app is separated into its own HTML, CSS, and JavaScript files (for example, dashboard.html, workstudy.html, etc.). This modular structure makes the code easier to read and maintain. We use Local Storage and session storage to keep data on the client side. According to MDN, the Web Storage API (localStorage and sessionStorage) provides key/value stores for browsers that “persist through page loads”. This means user data (like classes or tasks) stay saved between sessions without needing a server.
Overall, our documentation covers installation instructions, feature overviews, and team contributions. We structured it with headings and lists so it’s scannable. Good documentation ensures that anyone (our instructor or future developers) can understand the purpose of each file and who implemented what. By using Markdown, hyperlinks, and diagrams, we kept the README both human-readable and helpful for the project’s maintenance.
